# results/ — run output directory

This directory is the default output location of the scripts (configured via `output_dir` in
config.yaml). A copy of the author's own run outputs ships with the package so that
reproducers can compare file by file.

> ⚠️ **When checking numbers, use the "authoritative source" column of the table below.**
> Same-named files in this directory are outputs of script re-runs and need not be
> bit-identical to the authoritative archive (floating-point non-determinism + session
> differences; magnitude discussed in paper section S6).

## 2. ⚠️ `all_training_results.csv` / `grid_search_final_results.csv` caveat

These two files in this directory are **not** the full 256-run grid-search results — they are
residual rows of the smoke test `train/train_grid_search.py --max_runs 1 --epochs 1`
(a single `run_id=128` re-training record, `best_auc=0.9512`).

**All 256-run statistics of paper §3.1 (mean 0.9471±0.0094, range 0.9197–0.9665,
Run128 = 0.9665) come from `data/all_training_results.csv`.**
Using the residual files in this directory will give numbers that disagree with the paper.

Figure 1 (the overall workflow) is a diagram; it ships under `assets/` as **PDF (vector) + PNG
(4134 × 4572)**, with the editable source in `Figure1_overall_workflow_EN.html`. It is not produced
by any script in this package.

`fig_distribution_comparison.*` and `table_robustness.{png,pdf}` are optional/exploratory
outputs that are not numbered figures in the paper. They are **not included in this package, and
are no longer produced**: the rendering code has been removed from
`evaluate/generate_grid_figures.py`. The underlying numbers are still written —
`table_robustness_comparison.csv` — so nothing is lost analytically.

`demographic_analysis.png` (`preprocess/step6a_demographics_stats.py`) and
`Table_1_demographics.pdf` (`preprocess/step6b_generate_table1.py`) are likewise not part of the
released figure set; both scripts still write them. **Both run fully offline** — each reads only
`data/data_lists/subject_summary_20260531.xlsx` plus `config.yaml`, both of which ship with the
package:

- `step6b` writes `Table_1_demographics.xlsx` (plus a PDF, and a PNG preview when `pdf2image` and
  a system `poppler` are present; without them the PDF and XLSX are still written and the script
  exits 0). So Table 1 is reproducible from the bundled data alone — see step (8) of §3 in the
  main README.
- `step6a` writes `demographic_analysis.png` using only the plotting stack already listed in
  `requirements.txt` (matplotlib + seaborn) — no imaging, no GPU, no external binary.

## 4. Image formats

The `Figure_S1/S2/S3_*` series is written both as PDF (vector, for submission) and PNG (preview);
the main-text figures (`Figure_2`, `Figure_3`, `Figure_4`, `Figure_S4`) are PNG only (600 dpi).

## 5. Re-run vs archive: what may legitimately differ

Files in this directory are script outputs. Re-running the offline chain reproduces **all point estimates
bit-for-bit** (`report_metrics.json` and `baselines/baseline_tuned_grid.json` are byte-identical), but the
following may legitimately differ. The list was re-verified on 2026-09-26 by re-running the §3 and §5
offline chains (plus the two demographics scripts) in a clean copy and diffing every file against this
one: **exactly five files change** — the three supplementary PDFs, `Table_1_demographics.xlsx` and
`statistics_report.txt`.

| Item | Why it may differ |
|---|---|
| **Figure binaries** (`.png` / `.pdf`) | matplotlib version / font rasterisation. The PNGs reproduce **byte-identically**; the three supplementary PDFs (`Figure_S1/S2/S3_*.pdf`) differ in their embedded `/CreationDate` only — 6–7 bytes out of 32–47 kB, content pixel-identical. **No number changes.** |
| **`Table_1_demographics.xlsx`** | The cell values reproduce exactly (verified with `pandas.equals()` → `True`), but openpyxl re-writes the workbook, so `docProps/core.xml` carries a fresh `dcterms:created` / `dcterms:modified` timestamp. Byte comparison differs; content does not. |
| **`statistics_report.txt`** | Regenerated with a fresh `Report generated at: <date time>` line. Every other line is byte-identical — substituting the timestamp back into both versions makes them equal. |
| Bootstrap **CI / p** columns | They depend on the bootstrap count. Use the documented default (`run_baselines_tuned.py` with no arguments = 2000); a smoke run with `--n-boot 200` changes the CI bounds and floors p at 1/200 = 0.005. Point estimates are unaffected. |
| Untuned-baseline CSVs at the top level | `baselines/run_baselines.py` writes `baseline_5fold_cv.csv`, `baseline_external_cohorts.csv`, `baseline_test_set_performance.csv` and `cnn_ensemble_test_set_performance.csv` **here** (top level), whereas the tuned counterparts ship under `results/baselines/` with a `_tuned` suffix. Both label sets are correct; the directory split reflects the two scripts. |
| **Inference benchmark** (latency / model size) | **Not shipped in this directory** — see §1, and regenerate with `evaluate/run_inference_benchmark.py`. GPU latency is a hardware *snapshot*, not a reproducible constant: it varies with the GPU's thermal state, clock, driver and background load. Three measurements on the **same** RTX 5090 D gave **112.9 ± 1.8 ms**, **109.8 ± 6.2 ms** and **93.2 ± 1.4 ms** for the 5-fold ensemble, whereas the CPU figure stayed within 7% across the same three runs (3.42 / 3.43 / 3.20 s). The manuscript's `113 ± 2 ms` is the value archived in `reference_results/inference_benchmark/`; a re-run on your own machine will give a different number. Model size (parameters / bytes) is deterministic and does not vary. |

Two further files simply **appear** on a re-run (they are not shipped, and not part of the released
figure set — see §3): `Table_1_demographics.pdf` and `demographic_analysis.png`, written by
`preprocess/step6b_generate_table1.py` and `preprocess/step6a_demographics_stats.py`. Both scripts run
offline. Nothing else in this directory changes.
