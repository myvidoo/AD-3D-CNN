# `occlusion/` —— occlusion causal analysis (paper §2.5 / §3.3 / §4.3, supplementary S6)

> **English abstract.** This directory contains the complete, self-contained code for the
> occlusion-based causal analysis reported in the paper: region masks built from a
> Harvard–Oxford atlas, a 10-condition occlusion sweep (5 graded MTL masks, 3 matched
> controls, 1 extra fill strategy, 1 cross-subject transplant), and all downstream
> statistics, figures and numerical traceability checks. The analysis is organised as an
> explicit `step0 … step5` pipeline. The GPU part (5 scripts) needs model weights
> and preprocessed NIfTI images; the CPU part needs only `numpy` / `scipy` / `matplotlib` and
> reproduces every number quoted in the manuscript from the frozen intermediate results
> shipped in `reference_results/`. Run `python occlusion/verify_occlusion.py` to verify the
> archive end-to-end; `manuscript_checks/S6_numeric_traceability.md` maps each reported
> number to the exact field of a frozen product.

## 1. Where this experiment sits in the paper

| Paper location | Content | Corresponding script |
|---|---|---|
| §2.5 paragraph 038 | Definition of the occlusion analysis, voxel-share definition (MTL 1.83%, hippocampus 0.649%), forward reference | `step1_build_masks.py` |
| §3.3 paragraph 064 / S6 paragraph 065 | **Causal** evidence for the attention-focused region (at the level of regional information dependence) | `step3_occlusion_stats.py` |
| §4.3 paragraph 091 | Statement of regional information dependence in the discussion | `step3c_per_class_stats.py` |
| Supplementary S6 | 11 methodological addenda, numbered (1) methods and reproducibility controls … (11) inferences that should not be drawn (limitation notes); the report generated by `step5_report.py` opens with a "S6 (1)–(11) ⇄ report subsection / artifact" correspondence table | `step3*` `step4*` `step5_report.py` |
| Numerical traceability | paper number → artifact value path → value (87 items) | `manuscript_checks/S6_numeric_traceability.md` |

**Core conclusion (interpretation matrix A−)**: occluding the MTL significantly lowers the true-class probability (non-saturated n=80,
Wilcoxon p = 0.0081, effect size r = 0.296), and does so significantly more than the volume-matched controls
(C1 cortex p = 0.0357, C2 random sphere p = 0.0128); but it is **not significantly different from a hippocampus-only mask**
(C3, p = 0.190, not significant) ⟹ the evidence points to the **hippocampus itself** rather than the whole MTL,
so **MTL specificity for AD must not be claimed**.

## 5. Key definitions (essential reading before recomputing, to avoid misreading)

### 5.1 The main analysis must use the **non-saturated subset**

For 64/144 cases the top-1 probability is clamped by the float64 softmax to exactly `1.0`, so their Δp_true is identically 0 at the bit level
(the signal is swallowed by numerical saturation). Therefore:

* the saturation threshold is **`SAT_THR = 0.999999`** and is **based on the baseline p0 only**;
* the decision rule must be written `top1 > 0.999999` (giving n = 64 saturated / 80 non-saturated);
  writing `== 1.0` gives only 44 cases and turns the non-saturated subset into 100 cases —— every number comes out wrong.
* the script also outputs the all-samples definition `M1_delta_p_true_full` (n = 115) side by side, for reviewers to compare.

### 5.2 Definition of Δp_true

`Δp_true = p0[true class] − p_after[true class]`, and **a positive value = the true-class probability drops after occlusion**,
with **no second normalisation**.

### 5.3 Authoritative definition of mask volume

`step1_build_masks.py` fixes and self-checks:

| Mask | Voxel count | Share of brain |
|---|---|---|
| brain (`tmpl > percentile(tmpl[tmpl>0], 5)`) | 1735619 | 100% |
| MTL | 31764 | **1.8301%** |
| hippocampus | 11263 | **0.6489%** |
| C1 cortex (cort_23) | 32849 | — |
| C2 random sphere (10 spheres) | 31910 | — |

⚠ **The mask does not intersect brain** (`& brain` would give 1.7275%, which disagrees with the paper).
⚠ Three self-checks: ① voxel count; ② MTL / hippocampus ratio = **2.8197** (7.7140 if the mapping is misaligned);
③ MNI centroid (hippocampus ≈ (−1.0, −21.4, −14.4)).
⚠ HO labels = **XML index + 1** (the v45 corrected version); `8/18` and `33/34` are the **misaligned mapping from before v45, now retired**.

### 5.4 Three limitations that must not be deleted

1. AD-group McNemar **p = 0.25, not significant** (`perclass_stats.json → ad_specificity`);
2. the probability flow →CN **also appears** in the C2/C3 controls ⟹ **MTL specificity for AD must not be claimed**;
3. post-hoc stratification (saturated / non-saturated, per class) **must be labelled exploratory**.

## 6. Notes on the standardisation adaptation

The original research scripts under `27_occlusion_experiment/` were adapted under the principle "**change only the environment bootstrap layer, never the computation logic**":

* **removed** the machine-specific hard-coded paths inside the scripts (`BASE_CODE_DIR = r"D:\..."`, `OUT_DIR = Path(r"C:\...")` and so on);
* **replaced** them with same-named constants imported from `occlusion_config` (`OUT_DIR`/`OUT`/`FIG`/`CKPT_DIR`/`CSV`/`SAT_THR`/
  `SEED`/`DEVICE`/…), so **the computation logic in the body is unchanged line by line**;
* **prefixed a uniform header** (shebang, encoding declaration, docstring, line-by-line imports, `setup_stdout()`, `ensure_dirs()`);
* each file states its source and adaptation scope at the top (`# Source: 27_occlusion_experiment/<original name> (computation logic unchanged line by line…)`).

After adaptation the code passed a triple static check: `py_compile` compiles + an AST static undefined-name check (including lambda parameters,
comprehension targets and `except as`) + a residual absolute-path scan (with `# Source:` provenance comment lines exempted).

### 6.2 Two adaptation defects and their fixes (second round)

Both were found and fixed through the measurements in the table above; both are "environment bootstrap layer" issues and **involve no computation logic and no number that appears in the manuscript**:

1. **Work-directory creation accidentally deleted**: each original script carried a line `OUT_DIR/MASK_DIR/FIG.mkdir(parents=True, exist_ok=True)`,
   which was deleted along with the hard-coded paths during standardisation, leaving only the `ensure_dirs` import in the header and **no caller**.
   Consequence: when `AD3DCNN_OCC_WORK` points at a newly created directory, a `FileNotFoundError` is raised at the point of saving.
   Fix: call `ensure_dirs()` once after `setup_stdout()` in the 7 scripts.
2. **Fixed split not made absolute**: the `data/fixed_data_split.json` shipped with the repository stores only **relative file names**,
   and the scripts hand it straight to MONAI `LoadImaged` (MONAI resolves relative to the process CWD) → `FileNotFoundError`.
   The original scripts relied on the **absolute-path version** of the split provided by the external training module.
   Fix: `occlusion_config` generates `fixed_split_abs.json` in the work directory (sample order, `label` and
   `file_id` **exactly identical** to the original; only `file_path` is made absolute), with zero changes to the script bodies.

The per-file number of deleted lines / replaced lines / SHA1 of retained sections is recorded in the "change list" delivered with the code
(that list lives in the paper workspace and is not released with this code repository).

## 7. Reproducibility grading (S6 item (1))

| Level | Measured difference | Impact |
|---|---|---|
| **Within a session** (same process / cross-process / re-reading from disk / different construction path) | **bitwise identical (Δ = 0)** | the paper's numbers need no decimal-place margin |
| **Across sessions** (environment reloaded after a 12 h gap) | p0 max **9.449×10⁻⁴** (≤ 1.33×10⁻³) | argmax changes for **0/1440**; the sign direction is preserved for **1440/1440**; the saturated stratification **64/80** is unchanged ⟹ **not one number in the paper needs changing** |

⚠ This probability-level difference comes from **floating-point drift of the runtime environment / moment** (torch / cuDNN / driver) and is **unrelated to the code path**:
it has been measured that "this repository's module" and "the external original training code", inferring at the same moment on the same 3 cases, give
`max|Δp| = 0.000000e+00` (bitwise equivalent).

⚠ cuDNN automatically selects the convolution algorithm by batch size: `batch=1` and `batch=2` differ by 2.4×10⁻⁴.
Therefore all GPU scripts uniformly call `apply_determinism()` to enable deterministic algorithms.

## 10. Known limitations

1. **The weights were not compared file by file by MD5**: reproducing the full GPU chain requires the 5
   `fold_*_best_geo.pth` files in `weights_dir` to match those used at submission time (the archived log records the file size 76 844 757 B).
   The full GPU rerun of `step0` in this round gave accuracy and argmax **exactly identical** to the frozen artifacts, which is indirect evidence that the weights match.
2. **`step2b_rerun_sweep.py` and `step4c_determinism_probe.py` were not run as smoke tests**
   (they are auxiliary cross-process / determinism verification steps and are not on the required path to the numbers in the manuscript);
   their artifacts `occlusion_raw_rerun*.npz`, `donor_map*.json` and `det_probe.jsonl` are frozen with the repository,
   and the corresponding CPU-side rechecks (`step4a`/`step4b`/`step4d`/`step4e`) have **all passed**.
3. **After `OCC_MAX_SAMPLES` shrinks the sample set, the F3 cross-subject transplant condition cannot be compared bitwise with the full run**
   (the donor pool varies with the sample set); the other conditions remain comparable.
4. **Cross-session floating-point drift**: as described in §7, argmax and the direction of significance are both stable, but **bitwise comparison beyond the 4th decimal place is inadvisable**.
   Measured in this round: `max|Δp0| = 9.449×10⁻⁴` (≤ 1.33×10⁻³), with argmax preserved for 144/144.
5. The summary report generated by `step5_report.py` is a **data summary and interpretation** (not manuscript body text); it now has an
   **explicit numbering correspondence** with supplementary S6: the head of the report gives the "S6 (1)–(11) ⇄ report subsection / artifact" correspondence table, and each subsection heading
   also marks the S6 item it corresponds to. The report keeps the internal M1–M6 statistic numbering (consistent with the
   artifact key names of `step3_occlusion_stats.py`), so it is **not reordered** into the S6 (1)–(11) sequence. Because the random null distribution control is retired (see §8),
   §7·supplement outputs a skip notice (there is an `if NULL:` guard in the code), which is why it is shorter than the version at submission time.
   ⚠ That report **contains no manuscript body sentence**: the former "example paragraphs given in the form of manuscript body text" section has been removed entirely,
   while all its numbers remain in the data subsections of the report and can be rechecked item by item from `reference_results/`.
6. **Two deliberate points a reproducer will see in `verify_occlusion.py`** — both are recorded here so
   nothing is discovered by surprise:
   - **`_compare_figure()` uses a robust criterion rather than a strict `max|Δ|` rule.** Two renderings of
     byte-identical data can differ by a few 1/255 steps where a dashed line crosses a marker cluster, and
     a strict maximum would fail an otherwise perfect reproduction. The check therefore reports
     `max|Δpixel|` **and** the fraction of pixels differing by more than 8/255 for every figure, and fails
     only if that fraction exceeds 0.1 % or if any single channel exceeds 32/255. A genuine change — a moved
     marker, altered text, a different colour scale — alters far more than 0.1 % of pixels, so it is still
     caught. In this release five of the six figures are pixel-identical to the frozen copies, and
     `fig_occlusion_paired.png` has **0.0000 %** of pixels above the 8/255 threshold (`max|Δpixel| = 0.0157`,
     i.e. 4/255, confined to the anti-aliased overlap of the dashed diagonal with the saturated-sample markers).
     The frozen PNG itself was **not** modified.
   - **`patch_stats.json` → `P4_prob_destination.AD_to_CN_flip_ids` was re-ordered** to the deterministic
     order the script produces. The frozen file had been generated by an earlier script revision whose
     ordering followed the original (pre-de-identification) subject numbers — information that
     desensitisation necessarily removed — so that particular order could not be reproduced. The list holds
     the **same three samples** either way, no other field of the artifact changed, and `MANIFEST.md5` was
     rebuilt afterwards. The order of this three-element list carries no meaning.
